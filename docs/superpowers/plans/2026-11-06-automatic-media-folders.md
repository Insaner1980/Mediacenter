# Automatic Media Folders Implementation Plan

> Implement inline with focused regression tests; the user delegated routine design decisions and requested the behavior change.

**Goal:** Open standard media folders automatically and make an external folder a single picker action.
**Architecture:** A guarded native default-source command resolves system directories; shared library hooks select and scan sources. Reuse existing indexes, grants, source lifecycle and media screens.
**Tech Stack:** Existing Rust/Tauri, React/TypeScript, Vitest and Playwright; no dependencies.
**Spec:** ../specs/2026-11-06-automatic-media-folders-design.md

## Constraints and review focus

Preserve existing source/media identity and native file boundaries. Missing/disabled system directories must not broaden access. User choice must win over delayed initialization. Picker cancel must not mutate sources. Large scans must remain cancellable after navigation. Do not touch unrelated streaming documentation or user runtime state.

## Task 1: Native standard-folder resolution

Files: library/defaults.rs, library/mod.rs, commands.rs, lib.rs.
Interface: ensure_default_media_source(kind: MediaKind) -> Result<Option<String>, AppError>; no client-supplied path. Pure defaults::resolve and registration_root helpers support disposable tests; source_service::add_default uses the existing device gate and preserves UUID-less attachment confirmation. The command is declared in build.rs and enabled only in capabilities/main.json; permission schemas are generated by Tauri.
1. Add failing tests for existing directory/idempotence, missing directory, home/root rejection, ancestor reuse and overlapping descendant refusal.
2. Resolve Tauri picture/audio/video directories, acquire device gate and reuse source_service grant validation for the selected built-in directory.
3. Run focused Rust tests and native check; retain existing generated contracts.

## Task 2: Automatic selection and one-step folder opening

Files: backend.ts, SourceManagerProvider.tsx, useMediaLibrary.ts, LibraryFolderActions.tsx, three screens, fixtureServices.ts, unit/E2E tests.
1. Add failing tests: default selected/scanned, user selection beats delayed default, picker cancel unchanged, chosen folder selected/scanned and scan error visible.
2. Add backend adapter; initialize library scope before querying. Reuse shared scan ownership; show scan state/cancel and permit refresh rescan.
3. Replace prominent Manage folders with Open folder and an accessible secondary management button; preserve gallery/list composition and all playback functions.
4. Run typecheck/lint/unit/build, Rust tests/clippy/fmt, regenerate contracts and inspect unchanged output, targeted E2E and screenshot checks. Record changes and remaining hardware/package limits, commit task-owned files.

## Execution record

Application implementation: `3062630`. The user delegated the design choice. One independent review found UUID-less confirmation bypass, a dropped follow-up scan, and Music folder actions outside Library; all three were fixed with regressions. Native smoke then exposed missing command permissions; a failing permission boundary test was added and the main-window-only grant fixed. See ../../engineering/evidence/automatic-media-folders/acceptance.md for final results.
